# معماری کامل LocalAI Studio

## ۱. هدف

ساخت یک مرکز مدیریت هوش مصنوعی محلی که کاربر را از نصب دستی Runtime، پیدا کردن مدل مناسب، انتخاب Quantization و تنظیم پارامترهای پیچیده بی‌نیاز کند.

## ۲. لایه‌ها

```text
┌──────────────────────────────────────┐
│           رابط کاربری فارسی          │
│        React + TypeScript + RTL      │
└──────────────────┬───────────────────┘
                   │ Tauri IPC / Events
┌──────────────────▼───────────────────┐
│              هسته Rust               │
│                                      │
│ سخت‌افزار | مدل | پیشنهاد | دانلود   │
│ Runtime | حافظه | Benchmark | Chat  │
│ API | Process | Storage | Security  │
└───────────┬──────────────┬───────────┘
            │              │
     ┌──────▼─────┐  ┌─────▼─────────┐
     │   SQLite   │  │ Runtimeها     │
     │    SQLx    │  │ llama.cpp     │
     └────────────┘  │ Ollama        │
                     │ Transformers  │
                     │ vLLM / MLX    │
                     └───────────────┘
```

## ۳. Hardware Service

وظیفه:

- شناسایی سیستم‌عامل
- CPU و Instruction Set
- RAM
- GPU و VRAM
- Driver
- شتاب‌دهنده‌ها
- فضای ذخیره‌سازی

خروجی استاندارد:

```rust
struct HardwareProfile {
    id: String,
    timestamp: DateTime<Utc>,
    os: OperatingSystem,
    cpu: CpuInfo,
    memory: MemoryInfo,
    gpus: Vec<GpuInfo>,
    accelerators: AcceleratorCapabilities,
    storage: StorageInfo,
}
```

## ۴. Model Service

مدل‌ها باید از Provider دریافت و در ساختار داخلی استاندارد شوند.

```rust
struct ModelDescriptor {
    id: String,
    provider: String,
    repository: String,
    author: String,
    name: String,
    architecture: Option<String>,
    parameter_count: Option<u64>,
    context_length: Option<u64>,
    task: ModelTask,
    formats: Vec<ModelFormat>,
    variants: Vec<ModelVariant>,
    license: Option<String>,
    tags: Vec<String>,
    downloads: Option<u64>,
    likes: Option<u64>,
}
```

- Checksum

## ۸. Runtime Manager

Runtime باید Plugin/Adapter باشد.

Runtimeهای اولیه:

1. llama.cpp
2. Ollama
3. Transformers
4. vLLM
5. MLX

نسخه Production ابتدا llama.cpp را کامل پیاده‌سازی می‌کند و سایر Runtimeها از طریق Adapter اضافه می‌شوند.

## ۹. مدیریت حافظه

قبل از Load مدل:

```text
مدل + Context + KV Cache + Runtime Overhead + Safety Margin
```

با حافظه آزاد مقایسه شود.

در صورت کمبود:

1. کاهش GPU Layers
2. کاهش Context
3. CPU Offload
4. انتخاب Quantization سبک‌تر
5. پیشنهاد مدل کوچک‌تر

## ۱۰. Process Manager

هر فرآیند باید PID، Runtime، مدل، زمان شروع، CPU، RAM، GPU، VRAM، وضعیت و Exit Code داشته باشد.

```text

generation.token

generation.error
```

## ۱۳. امنیت

## ۱۴. Offline-first

بعد از نصب مدل، این قابلیت‌ها بدون اینترنت کار کنند:

- اجرای مدل
- چت
- API محلی
- Benchmark
- مدیریت مدل

این موارد نیازمند اینترنت هستند:

- جستجوی مدل جدید
- دریافت Metadata جدید
- دانلود
- بروزرسانی Runtime

## ۱۵. تست

پروفایل‌های تست:

- سیستم ضعیف: RAM 16GB و GPU مجتمع
- سیستم متوسط: RAM 32GB و VRAM 8GB
- سیستم قدرتمند: RAM 64GB و VRAM 24GB
- Apple Silicon

سناریوی E2E:

```text
اجرای برنامه
→ اسکن سخت‌افزار
→ جستجوی مدل
→ پیشنهاد
→ نصب
→ دانلود
→ اعتبارسنجی
→ اجرا
→ چت
→ Benchmark
→ API
→ توقف
```

چرخه اجباری:

```text
پیاده‌سازی

→ اجرا
```
